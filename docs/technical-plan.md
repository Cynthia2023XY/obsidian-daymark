# Daylane：重要事项与专注日历插件技术方案

## 1. 定位与命名

显示名称：**Daylane: Chinese Holiday Calendar**，独立名称为 Daylane，中文说明为“中国节假日与待办日历”。名称表达事项沿日期推进，既适合固定排期，也适合未完成待办流转。番茄钟是独立的辅助工具，不改变日历以重要事项为中心的定位。

建议插件 ID：`daylane`；仓库名：`obsidian-daylane`；事项属性前缀：`daylane-`；日历代码块语言：`daylane`。本仓库按此名称独立实现；本地开发不等于已提交市场申请。

备选名称：Dayweave（编排日期与事项）、Agenda Loom（日程织机）。截至 2026-10-11，对官方插件列表的名称与 ID 检查未发现这三个候选的匹配项；Dayflow、Daymark、Day Planner 已被使用。未发现匹配不代表名称已保留，也不代表商标检查通过；发布前重新检查。

产品描述建议：Manage important events and rolling to-dos in calendar views, with Chinese public holidays, embedded calendars, and a standalone focus timer.

## 2. 已确认需求与首版边界

| 能力 | 已确认需求 | 首版建议 |
| --- | --- | --- |
| 重要事项 | 日历中的重要事项管理 | 创建、编辑、完成、取消、删除、调整日期 |
| 待办流转 | 当天未完成事项可自动移到下一天，允许配置 | 全局开关与单条覆盖，补处理离线期间的过期待办 |
| 中国节假日 | 排期时直接查看假期 | 放假、调休上班、普通周末分开标记 |
| 大屏日历 | 和同事查看、讨论排期 | 主工作区月历，日期格直接展示事项标题与跨日事项 |
| 代码块日历 | 在笔记中渲染日历 | 指定月份、项目筛选、节假日显示、交互开关 |
| 番茄钟 | 独立使用、支持自定义时长 | 专注与休息两种模式，开始、暂停、继续、重置、到时提示 |

首版不加入周期笔记创建、第二日记、字数统计、连续记录、封面图片、小时级排期、重复事项、系统日历同步或多人实时协同。和同事对排期按共享屏幕使用设计。

跨日事项是方案推荐：联调、验收等经常占用多天。番茄钟的休息模式也是方案推荐；即使不需要休息，用户也可以仅运行专注模式。

## 3. 独立开发与现有项目关系

新建独立仓库，从官方插件模板或最小 TypeScript 插件工程开始。保留现有 Calendar Plus 作为日常使用工具和行为参考，不把其代码批量搬入后改名。

现有项目的事项与节假日模块已形成业务边界，但日历主组件仍依赖多类周期笔记状态，内嵌日历加载字数、连续记录、任务、第二日记、封面等数据源。新项目直接建立“事项数据—节假日—日历展示”的链条，避免继承这些关系。

可以复用自己的需求描述、验收案例和对原问题的认识。已知的索引启动竞态、异步读取过期结果、目录重命名遗漏等作为新实现的验收案例。某段代码是否由自己独立编写，应根据提交历史和依赖判断；不能仅因为位于自己 fork 中就视为原创。

README 说明 Calendar Plus 对交互需求的启发，并明确独立维护。第三方依赖单独保留许可证。Obsidian 目前对 fork 的官方收录有额外要求，独立项目也不能把实质继承代码隐藏成原创；独立重写不保证市场审核结果。[开发者政策](https://docs.obsidian.md/community-directory/developer-policies)

## 4. 数据模型与文件存储

### 4.1 一条事项对应一篇 Markdown

事项保存在用户配置的目录，默认 `Daylane/Items`。按创建年份归档，而不是按当前计划日期自动搬动文件。流转只更新日期属性，文件路径稳定，避免跨年流转破坏笔记链接。

文件名采用“安全标题＋短 ID”，日期通过属性管理，不要求从文件名解析。标题更改默认只更新属性，重命名作为独立动作。完整 ID 是事项身份，路径是当前存储位置。

示例属性：

```yaml
---
daylane-schema: 1
daylane-id: "7b43f33d-9e83-4515-a956-1a8c1f89c1b5"
daylane-kind: todo
title: 整理接口文档
status: open
scheduled: "2026-10-11"
original-scheduled: "2026-10-11"
deadline: "2026-10-16"
rollover: inherit
rollover-count: 0
project: 基金营销
color: blue
created: "2026-10-11T09:00:00+08:00"
updated: "2026-10-11T09:00:00+08:00"
---
```

正文自由保存说明、链接、讨论记录。所有日期属性规范为 `YYYY-MM-DD` 字符串，避免 YAML 日期对象和时区换算造成偏移。

### 4.2 类型与日期语义

| 字段 | 含义与约束 |
| --- | --- |
| daylane-kind | `todo` 待办，或 `event` 固定日程 |
| status | `open`、`completed`、`cancelled`；首版不增加执行中状态 |
| scheduled | 待办准备执行的日期，可被流转更新 |
| original-scheduled | 初次计划日期，自动流转与普通改期不覆盖 |
| deadline | 待办可选截止日期，自动流转不改动 |
| start / end | 固定日程的起止日期，结束日期包含当天；单日时 end 等于 start |
| rollover | `inherit`、`auto`、`off`；仅对待办生效 |
| rollover-count | 实际成功流转次数，不等于经过的天数 |
| last-rollover-from / last-rollover-to | 最近一次流转的来源与目标日期 |
| completed-at | 完成时间，重新打开事项时清除 |
| project / color | 可选项目分组与预设颜色 |

待办首版要求计划日期；固定日程要求有效起止日期，end 不得早于 start。过期固定日程保留原日期，不自动移走。待办超过 deadline 且未完成时显示逾期，流转不消除逾期。

支持完成后重新打开：若它的计划日期已过且允许自动流转，则按当前规则重新进入当天或下一个工作日；操作后明确展示最终日期。

## 5. 事项仓库与索引

事项 Markdown 是唯一事实来源，内存索引可以随时重建。插件配置文件只保存目录、显示偏好、流转与番茄钟默认设置，不另存完整事项副本。

首次加载先订阅文件创建、修改、删除与重命名，再扫描配置目录。直接读取 Markdown 并解析 frontmatter，不能把“Metadata Cache 尚未提供数据”视为“文件没有事项”。需要从原始文本建立首次索引，缓存事件可作为额外刷新信号。

按 ID 和文件路径定位事项；查询指定月份时使用日期范围交集，不为跨度很长的日程预先展开全年每日副本。同 ID 出现在多个文件时报告冲突，不静默合并或删除文件。

异步读取结果只在仍对应该文件的最新状态时入库。删除或重命名后，旧读取不能重新插入旧路径。目录重命名和删除处理其后代事项。读取失败保留已有索引并提示；初次失败文件进入可重试列表，不报告成功扫描。

插件修改属性使用公开文件 API，并仅更新自己负责的字段；保留正文和未知属性。写入前重新核对最新状态，避免在用户刚完成待办后又执行旧的流转决定。YAML 排版可能由 API 重排，保证业务字段与正文内容保留，不承诺字节级不变。

建立索引后的新增、修改、删除向各视图发布同一份变化通知。多个视图独立选择月份和日期，共享事项数据；关闭某个视图不停止其他视图和插件服务。

## 6. 待办自动流转

### 6.1 配置与规则

全局自动流转默认关闭；单条待办可跟随设置、明确开启或明确关闭。新增待办默认跟随设置。

触发时以本地当天为基准：只处理计划日期早于今天、状态 open、类型 todo、最终允许自动流转的事项。今天仍未结束的待办不会提前移到明天。

| 设置 | 目标日期 |
| --- | --- |
| 自然日模式（默认） | 今天 |
| 工作日模式（可选） | 今天是工作日则今天，否则从今天向后找第一个工作日 |

工作日模式使用调休上班优先于周末的判定，正式放假优先于普通工作日。缺少相关年度数据时不推测官方安排：该条自动流转暂缓并提示，用户仍可手动改期或切换自然日模式。跨年寻找目标时同样检查数据覆盖。

插件启动并完成索引、跨过本地午夜、回到前台时检查；运行期间按周期校验本地日期，以补偿定时回调延迟。插件关闭时不运行，重新打开后直接补到当前目标日期，无需逐日写入。

截止日期不动；首次计划日期不动；最近来源与目标日期及次数随成功写入更新。一次离线补流转只计一次，界面可以另行计算距首次计划的天数。

### 6.2 执行与失败处理

流转由插件级服务统一执行，不由每个日历实例各自触发。对同一批事件合并检查，防止启动、前台和日期变化同时启动重复处理。它针对可明确复现的事件重叠，不引入通用分布式锁体系。

每条写入时检查当前类型、状态、日期和流转设置仍满足条件。目标日期已等于当前日期则不写；写入成功后刷新索引。失败项保留原日期，汇总成功与失败数，支持重试。不同设备并发修改仍由用户的 Vault 同步机制处理，不声称插件提供跨设备事务。

提供单条“移到明天／选择日期”和批量“移到今天”。未允许流转的过期待办列入“此前未完成”，不会只藏在过去月份。

自动写入不承诺通过编辑器 Ctrl+Z 撤销。提供“撤回最近一次流转”：按记录只恢复计划日期仍等于该次目标的事项，已经再次改期、完成或被外部改动的项跳过并解释。最近批次恢复信息需持久化；重启后也能恢复，记录只保留最近一次批次。该操作不会恢复其他业务字段。

## 7. 日历与查看入口

### 7.1 大屏月视图

通过命令和侧边栏图标打开主工作区页签，支持将该页签放到独立窗口。大屏不依赖真正的系统全屏；窗口最大化即可用于共享屏幕。

月视图直接显示事项标题、状态、颜色与节假日，跨日固定日程显示连续条带，跨周时拆成展示片段但仍属于同一事项。同格溢出显示“还有 N 项”。

工具栏支持上一月、下一月、今天、月份跳转、项目与状态筛选。单击日期选择当天，明确的新建按钮或日期双击创建事项；单击事项打开详情或对应笔记。首版通过表单改期，不必引入拖拽。

右侧或下方显示选中日事项，并提供“今天待办／此前未完成”。窄屏自动改为上下布局。完成事项默认弱化，用户可隐藏。展示模式隐藏创建与编辑控件，便于投屏；它是当前视图的交互限制，不是对文件的权限控制。

### 7.2 日历代码块

使用独立语言标识 daylane，首版不接管 calendar-plus，避免两个插件同时处理相同代码块。

````markdown
```daylane
month: 2026-10
project: 基金营销
show-holidays: true
show-completed: false
interactive: true
```
````

month 支持固定月份与 `current`；默认 current。project 可省略，省略表示全部项目。interactive 默认 true，false 时隐藏修改入口。展示仍来自同一个事项仓库，不在代码块另存事项内容。

固定 month 不因翻月改写笔记，翻月属于实例临时状态。多个代码块月份独立，项目筛选独立，事项修改互相刷新。配置错误在对应块显示可理解的提示，不中断整篇笔记渲染。

首版验证阅读视图与实时预览中的渲染；源码模式保留原始代码块。渲染子节点卸载时清理订阅和 DOM，避免反复切换视图后重复监听。

### 7.3 侧栏

作为第二阶段入口，复用月历数据与操作，使用紧凑日期格和当天列表。不加入旧插件的日记打开、周编号笔记或周期笔记设置。

## 8. 中国节假日

采用随插件发布的离线年度数据，记录年份、官方来源链接、公告日期和版本。每次发布前核对当年及未来已正式公布的安排，不按农历算法猜测放假调休。

展示分为正式放假、调休上班、普通周末与普通工作日。正式放假标休，调休上班标班；鼠标悬停或触摸详情显示节日名称。

未覆盖年份在月历中显示“该年正式节假日安排未收录”，普通周末仍可显示，但不得标成已确认假期。首版通过正常插件版本更新数据，不在运行时自动下载执行内容。以后如增加远程数据更新，需另行定义来源、校验、网络说明与失败回退。

## 9. 独立番茄钟

### 9.1 产品范围

番茄钟独立于事项，不需要选择事项、项目或日期，也不自动完成事项。日历视图没有打开时仍可使用番茄钟。

首版默认专注 25 分钟、休息 5 分钟；设置中均可自定义，建议范围为 1—240 分钟的整数。运行前在番茄钟面板可临时覆盖本轮时长，不影响默认值。更改设置只作用于下一轮，不截断正在运行的轮次。

提供专注／休息模式切换、开始、暂停、继续、重置。模式切换在空闲或结束时直接生效；运行中切换视为放弃当前轮，界面明确标示此行为。

到时提示并进入 finished，不自动开始下一阶段。可以点击“开始休息”或“再专注一轮”。首版不加入长休息周期、自动循环、专注统计、历史记录或事项绑定。

### 9.2 入口与状态

独立番茄钟面板可以放在侧栏；桌面状态栏显示模式与剩余时间，点击打开面板；命令提供打开、开始／暂停、重置。移动端不依赖状态栏，使用面板和命令入口。

整个插件实例只有一个 TimerService，多个面板与弹出窗口显示同一轮倒计时，不各自建立计时器。番茄钟模块可以单独关闭，关闭时结束当前轮并清理提示资源。

状态分为 idle、running、paused、finished；模式分为 focus、break。状态中记录本轮原始时长、运行截止时间、暂停剩余时长和轮次标识。

### 9.3 计时和提示

运行时依据“截止时间减当前时间”计算剩余秒数，不能每秒将变量减一。刷新定时器只负责重绘与检查完成。电脑睡眠或应用在后台期间仍按实际经过时间计时；恢复后若已结束，补发一次完成提示，不循环补发多轮。

暂停时冻结剩余时长；继续时根据剩余时长建立新的截止时间。刷新显示取剩余时间的向上取整，避免刚开始便少显示一秒。

后台定时回调存在节流，因此不承诺到时提示在睡眠或应用挂起时实时触发；返回前台后立即重新检查。[MDN 定时器说明](https://developer.mozilla.org/en-US/docs/Web/API/Window/setTimeout)

每轮完成提示只执行一次。默认使用插件内通知与面板醒目提示；提示音作为可关闭选项，在用户开始计时时初始化音频，失败时保留文字提示。提示音采用自生成短音或明确许可的本地资源，不从网络拉取。

首版计时会话只保存在当前插件运行实例的内存中，关闭 Obsidian、禁用插件或重新加载插件会停止本轮；重新打开显示空闲。默认时长等偏好持久化。这样避免同步插件配置后另一台设备意外继承正在进行的计时；如未来需要跨重启恢复，应使用设备本地的会话存储单独设计。

## 10. 技术选型与模块划分

建议 TypeScript、Obsidian 公开 API、esbuild、原生 DOM 与 CSS Grid/Flex；首版没有必要为月历和一个计时面板引入完整日历库或前端框架。日期计算统一封装，使用本地日期语义，避免 `new Date('YYYY-MM-DD')` 的 UTC 解析直接参与日历运算。

日期领域服务统一处理月份范围、闰年、星期和跨日交集。节假日按字符串日期查表；午夜调度必须按下一次本地午夜计算，不固定加 24 小时，以适应夏令时环境。

| 模块 | 职责 |
| --- | --- |
| main | 生命周期、命令、视图注册、服务初始化与卸载 |
| domain | 事项类型、日期规则、校验、查询与流转判定 |
| repository | Markdown 读取、属性修改、增量索引 |
| rollover | 流转触发、执行、汇总与最近批次恢复 |
| holidays | 离线年度数据、日期分类与覆盖范围 |
| calendar | 共享月历组件、布局、跨日事项展示与交互 |
| views | 大屏、侧栏与当日事项布局 |
| markdown | daylane 配置解析和渲染生命周期 |
| timer | 独立计时状态机、面板、提示与可选状态栏 |
| settings | 目录、日历显示、流转、番茄钟偏好 |
| migration | 手动导入旧 Calendar Plus 事项 |

事项服务与 TimerService 没有互相调用。日历宿主复用同一个展示模块。视图注册、代码块处理与 frontmatter 修改优先使用公开 API。[Obsidian API 定义](https://github.com/obsidianmd/obsidian-api/blob/master/obsidian.d.ts)

新增代码按工作区中文注释规范编写；函数内说明采用 //，函数、变量、常量、类型等声明前采用 /** */。业务规则不绑定 UI，便于直接验证。

## 11. 配置与命令

| 配置组 | 首版配置 |
| --- | --- |
| 事项 | 存储目录，默认颜色 |
| 日历 | 每周起始日，已完成事项显示，节假日显示 |
| 流转 | 自动流转开关，自然日／工作日模式 |
| 番茄钟 | 启用开关，专注时长，休息时长，提示音开关 |

命令包括打开日历、新建事项、打开今天待办、批量移到今天、撤回最近流转、插入日历代码块、打开番茄钟、番茄钟开始／暂停、重置番茄钟，以及手动导入旧事项。

状态栏只承担轻量的计时展示，不塞入完整事项操作。设置只保留会影响实际使用的选项，避免重新发展成旧插件的大量设置。

## 12. 旧事项迁移

通过手动导入命令选择旧事项目录。识别旧 `calendar-plus-type: important-event` 标记，将 date、title、status、color 等映射为新模型。默认导入为单日固定事项且 rollover 为 off；没有证据时不能把所有旧事项推断为可自动顺延的待办。

导入预览列出数量、目标目录和无法识别项；执行时复制到新目录，保留原文件与正文。记录来源路径和内容指纹，用于识别重复导入与源文件更名，冲突需展示，不覆盖已编辑的新事项。用户可在新插件里再将适合的事项切换为待办并启用流转。

原有 calendar-plus 代码块继续由原插件渲染；新插件提供对应 daylane 配置建议，转换由用户显式执行，不扫描并自动改写整个 Vault。

## 13. 验证重点

| 范围 | 必须验证的行为 |
| --- | --- |
| 文件与索引 | 冷启动时缓存未就绪仍加载事项；修改、重命名、删除、目录更名；旧异步读取不能恢复已删除项 |
| 数据完整性 | 属性写入保留正文与未知字段；读写失败不伪报成功；重复 ID 明确报告 |
| 日历 | 闰年、月首星期、跨月跨年事项、同格溢出；多个实例共享数据但月份独立 |
| 节假日 | 周末调休上班、工作日放假；缺失年度提示及工作日流转暂缓 |
| 流转 | 默认关闭、单条覆盖、日期小于今天才流转；固定日程与已完成项不移动；离线补处理；截止日期不变 |
| 流转恢复 | 同日重复触发不重复写；失败部分可重试；撤回只恢复未被再次修改的计划日期 |
| 代码块 | 阅读视图、实时预览、源码模式；错误配置、卸载再渲染、多块刷新 |
| 番茄钟 | 自定义时长、暂停继续、重置、模式切换；后台延迟与睡眠恢复只补一次提示；多面板共享状态；卸载清理 |
| 迁移 | 旧文件保留、状态映射、默认不流转、重复导入识别、部分失败报告 |

用自动化测试覆盖日期、流转、索引竞态和计时状态机；用 Obsidian 中的实际操作验证视图布局、代码块生命周期、弹出窗口和提示音。构建成功不等于这些运行行为已通过。

## 14. 实施顺序与交付条件

1. 初始化独立仓库与许可证，建立事项模型、目录和读取索引。验收：新建事项可保存、重启后恢复、普通笔记不被误识别。
2. 实现大屏月历、单日与跨日事项编辑、完成和改期。验收：可直接用它和同事查看排期。
3. 加入节假日与代码块，完成跨视图刷新。验收：大屏与内嵌显示一致，配置错误不影响其他笔记内容。
4. 加入自然日自动流转、工作日规则和最近批次撤回。验收：日期与截止边界正确，失败不丢事项。
5. 加入独立番茄钟。验收：不创建任何事项也可完整使用，时长可配置，后台恢复正确。
6. 加入迁移、侧栏紧凑视图，完成桌面和移动端适配验证。若移动端没有验证通过，首发清楚声明桌面范围，不能提前声称完整兼容。
7. 准备 README、演示、数据覆盖说明、依赖许可证、发行产物与市场提交。每次版本发布重新核对名称与官方要求。

首版优先实现独立番茄钟而不增加计时统计和任务联动；后续功能仅在有实际使用需求时扩展。

## 15. 当前结论

建议采用 Daylane 作为工作名称，独立开发重要事项与待办日历。用 Markdown 保存事项，大屏和代码块共享展示，按配置流转未完成待办，独立番茄钟支持自定义专注与休息时长。

本方案中的默认关闭自动流转、自然日模式、25/5 分钟时长、手动开始下一阶段、重启不恢复计时和首版技术选型均为建议默认值，可以在编码前调整。实施状态与已验证范围见 README 和 docs/verification-report.md；市场提交与日常 Vault 部署需单独执行。
