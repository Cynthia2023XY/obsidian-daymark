# Daymark：单日重要事项与待办箱改造方案

## 1. 评估结论

建议对现有 Daylane 做一次明确的产品收敛，不再次新建仓库。事项仓库、节假日服务、番茄钟、索引竞态处理和日期运算保留；跨日排期、项目、颜色、截止日期、取消状态和复杂编辑表单整体移除。

产品定位改为：**带中国正式节假日的单日重要事项日历，支持未完成事项顺延与待办箱，附独立番茄钟。**

正式显示名称确定为 Daymark - Chinese Holiday Calendar，中文称“每日要事”，突出单日重要事项。为兼容现有用户笔记与配置，仓库名采用 obsidian-daymark，插件 ID 按最终发布要求改为 daymark-chinese-calendar；保留 daylane-* 属性和 daylane 代码块语言；显示名称变更不触发数据迁移。

作者显示名称统一改为 **Cynthia Ding**；GitHub 用户名与仓库归属仍可保留 Cynthia2023XY。后续修改 manifest、package 元信息、README 署名和 LICENSE 的本人署名，不改动第三方署名。

本次只评估和制定方案，不修改插件源码、不批量改写现有事项。当前代码已读取，图片参考已查看，同名创建已执行内存边界模拟。

## 2. 当前行为核查

### 2.1 自动流转现在如何发生

当前全局 autoRollover 默认 false、rolloverMode 默认 calendar。单条事项仍有 inherit、auto、off 三种覆盖方式。

满足以下条件才进入自动流转：类型 todo、状态 open、scheduled 早于本地今天，且单条或全局规则允许流转。固定日程、完成、取消、今天与未来事项不参加。

检查触发：插件启动扫描完成并等待工作区就绪、下一次本地午夜、窗口回到前台、页面恢复可见、运行中检测本地日期改变，以及保存设置／重新打开事项后的检查。当前定时器每秒同时刷新番茄钟并检查日期是否改变，不是每秒重扫 Vault。

自然日模式直接移到今天；工作日模式移到今天或从今天向后找到的首个正式工作日。插件关闭时没有后台进程，重新打开补处理。

目前离线多天只执行一次日期写入并加一次 rollover-count。用户确认流转次数是客观存在的记录，因此保留按实际成功自动改期累计的定义；不能把未运行的每个自然日虚构成已经发生的流转。最大次数不是严格的“经过多少天”上限。

当前无自动默认打开侧栏逻辑，打开侧栏依赖命令。新方案增加工作区就绪后的查找／创建与展示。

### 2.2 同名创建的实际模拟结果

模拟边界使用生产 ItemRepository 与内存 Vault，在目标目录预放 `测试b.md` 后创建两条“测试b”：

- 原有测试b.md 内容没有被覆盖。
- 新文件分别生成 `测试b-145f2ad4.md` 与 `测试b-1e277ec7.md`，仍使用随机后缀。
- 正文默认 `# 测试b`，属于一级标题。

这证明当前避免覆盖依赖随机文件名，尚未实现用户要求的“标题＋数字”处理。上述是存储边界模拟，不是原生 Obsidian 实机测试。

## 3. 日历和事项交互

### 3.1 按修改版 Calendar Plus 的视觉重做

以用户提供的紧凑日历截图及当前修改版作为验收参考：月份／年份标题、左右箭头、今天按钮、星期行、日期格、选中背景、今日颜色、相邻月淡化、休／班角标、红色事项圆点和下方事项列表。

独立页面和侧栏使用同一套日历，不再采用“大屏日期格里放任务卡片＋右侧详情”的布局。独立页面放大的是可读性和容器，而不是增加新的交互。事项列表都位于日历下方。代码块同样复用此组件，保留日期选择和是否允许交互的实例配置。

移除项目、状态筛选器、展示模式、跨日条带和日期格里的事项标题。完成与未完成默认同时显示；某天有事项即显示红点，不提供颜色选择。

“完全一致”的验收在相同 Obsidian 主题、缩放和容器宽度下比较。保持视觉和交互，用独立实现重做，不直接复制旧插件的周期笔记和 UI 源码。日期导航中的年份与月份不再打开周期笔记。

### 3.2 默认侧栏

启动后等待工作区就绪：已有本插件侧栏页签时恢复并显示；没有时在侧栏创建一次。重新启用、打开命令和布局恢复不得堆叠重复页签。

用户当前在别的笔记工作区时不跳到大屏日历。默认展开侧栏，但不抢主编辑区焦点。大屏继续由命令打开。多窗口通过公开工作区 API 处理，原生验收要覆盖关闭、重开与布局恢复。

### 3.3 新建与列表

单击日期选中并刷新当天列表；双击日期、点击列表下“＋ 添加重要事项”都打开同一个简单弹窗。

弹窗仅有：标题“新建 YYYY-MM-DD 重要事项”、事项名称输入框、“创建重要事项”按钮。Enter 提交，Esc 关闭，空名称提示。日期由当前选中日决定，不出现类型、状态、流转规则等创建配置。

列表每条仅显示：完成复选框、事项标题、删除入口。点击标题打开 Markdown 文档；勾选切换完成状态。完成项保持可见并淡化／划线。复杂动作进入右键菜单，不在每行常驻多个按钮。

### 3.4 手动流转右键菜单

使用 Obsidian 公开 Menu 接口，在事项行右键展示：

1. 移到下一个工作日／自然日，依据当前设置，基准取今天与该项日期中较晚的一天。
2. 选择日期……，打开一个小日期选择弹窗，选择今天或未来日期并确认。
3. 移入待办箱。
4. 删除／移除重要事项，依据删除方式设置显示明确名称。

历史事项和待办箱可增加“移到今天”这一上下文动作。右键菜单不会先执行标题打开动作；日期弹窗不重新引入完整事项配置表单。未来移动端用长按或仅移动端的更多菜单作为替代入口。

自动流转计数是累计的客观记录：手动指定日期、移入待办箱、从箱中重新安排、批量移到今天、完成或重新打开都不清零，也不增加自动流转次数。累计已达上限的事项重新安排后可以显示在指定日期，但下一次需要自动顺延时会再次进入待办箱。

## 4. 文件名、正文和事项标题

新事项直接写入配置的事项目录，不再自动附加创建年份子目录。读取该目录及其子目录，兼容已存在的按年归档文件，但不自动搬动旧文件。

新建文件顺序：`测试b.md` → `测试b 1.md` → `测试b 2.md`。碰撞检查覆盖任何已有文件／路径，不限已识别事项。标题中的非法路径字符仍替换为安全字符，并在发生调整时显示实际文件名。

创建瞬间如果另一个窗口或同步进程占用了候选名称，确认确实为路径占用后尝试下一个编号；其他写入错误直接报告，不把权限或 I/O 错误当作重名重试。不覆盖、不把新事项合并到已有笔记。

新正文使用 `## 测试b`。列表标题建议直接采用 file.basename，不再持久化一个需要手动同步的 YAML title。修改文件名后列表立即变更；仅修改正文一级／二级标题也不会导致事项丢失，识别不依赖正文标题。文件名与正文标题可以不同，插件不擅自重写用户正文。

旧文件去随机后缀和标题降级作为单独可预览的迁移动作，不在启动时自动执行。确认后使用 Obsidian 的重命名 API 更新关联链接；只处理可验证为插件生成的标题行，不把用户正文中的其他一级标题统一降级。

用户示例里的 `calendar-plus-type`、date、title、status、color、created 属于旧格式；`date created`、`date modified` 属于其他笔记元信息，不能仅因出现在事项文件中就删除。

### 5.2 新建事项只写四个专属字段

```yaml
---
daylane-type: important-event
daylane-date: "2026-10-12"
daylane-status: open
daylane-rollover-count: 0
---
```

随后正文为二级标题。使用专属字段避免抢占笔记原本的 date、status、title，也让“只移除事项属性”可以明确且安全地删除四项，不误伤通用笔记元信息。

待办箱版本没有 daylane-date，但保留另外三个字段。日期缺失是明确的业务状态，不是解析失败。完成／未完成与有没有日期独立：待办箱也能有完成项，重新打开仍留在箱中，直到手动安排日期。

缺少计数默认为 0；缺少状态可按未完成兼容读取，但保存时补为 open。状态值非法、日期格式非法要报告，不把错误日期默默当作待办箱。空日期视为未安排，保存时统一删除日期键。

## 6. 事项识别与全库扫描

正常模式必须同时满足：文件位于配置目录或子目录；`daylane-type: important-event`。后者是专用 YAML 属性，不要求用户再增加 tags 列表标签。

高级设置“仅扫描事项目录”默认开启。关闭后只解除路径条件，标记条件仍必须成立；新文件依然写入配置目录，不根据最近打开位置随意创建。

文件名、正文标题、UUID、文件内的旧普通 title 属性都不是识别条件。更名在允许目录内不会丢失；正常模式下移出目录会停止展示，是范围规则的预期行为；全库模式下移到 Vault 其他普通目录仍可展示。

全库扫描仅在启动、切换范围或显式重建时做一次初始扫描。平时根据文件创建／修改／删除／更名事件更新对应文件；目录更名只处理受影响后代，不对每次更名执行全库重扫。

初始化仍先监听后扫描，不能因 Metadata Cache 为空而永久漏掉事项。大 Vault 使用有限并发、分批读取并让出渲染时间，显示扫描进度与错误数；初次发现所有 marked 笔记仍有真实 I/O 成本，不宣称零性能影响。之后自动流转只查询事项内存索引，不每天重新读取所有 Markdown。

## 7. 新自动流转规则与上限

### 7.1 统一启用与工作日默认

按用户最新的精简设置清单，建议删除全局自动流转开关和单条覆盖：所有未完成且带日期的重要事项自动顺延，默认工作日模式。这里是明确的行为变更，不只是隐藏开关；升级前要展示说明，完成迁移确认后才执行第一次自动流转。

自然日：从事项当前日期移到下一个自然日。工作日：从事项当前日期向后找下一个正式工作日，必须严格晚于当前日期。正式休假与调休优先于普通星期。缺少相应年度官方数据则该项暂缓，绝不推测正式工作日，也不把暂缓计为成功流转。

触发仍在启动、午夜、恢复前台等时点。只处理日期早于今天且未完成的项，今天和未来不提前移动。插件关闭时不执行，回来后补处理。

### 7.2 离线补处理和计数

建议按实际成功执行的自动日期变更累计，一次自动处理最多对一篇笔记写一次。插件持续运行时，每到新的日期把过期未完成事项移到下一个自然日／工作日；离线补处理可以直接落到今天或当前规则下的下一工作日，实际只发生一次改期，因此计数只加 1，不补造关闭期间的流转记录。

例：自然日模式，计划 10 月 9 日，10 月 12 日才重新打开，实际自动改期 9→12，计 1 次。若插件在 10 日、11 日、12 日分别成功执行 9→10、10→11、11→12，才是 3 次客观记录。

例：工作日模式，2026 年 10 月 10 日是调休上班，10 月 11 日是周日。持续运行时 9→10 是一次，10→12 是第二次；如果期间未运行，12 日只实际执行 9→12，则计 1 次。工作日判定仍不能按普通周末规则把 10 日跳过。

计数与自动改期在同一次属性写入内更新，避免日期变了但次数没有同步。重复聚焦、重扫、同日检查、读取失败、数据缺失与手动改期不增加计数。写入前重新核对最新状态；用户已经完成或手动改期的旧候选不能被覆盖。

### 7.3 待办箱上限的建议定义

最大次数默认 5，设置值为正整数；此项属于用户新增的高级配置。上限改变不截断或回写历史累计次数。

用户已确认：允许自动顺延 5 次，第 6 次需要顺延时进入待办箱。入箱只是取消日期属性，计数仍为 5，不清零，也不制造一次没有目标日期的第 6 次自动改期记录。

达到入箱条件：删除 daylane-date，保留事项标记、未完成状态和计数；不物理移动 Markdown，不改变文件名和正文。这里“移入”是从日历进入未安排事项集合，不是文件夹搬迁。

离线很久时按当前累计次数与当前目标日期做一次决策，不逐日改写历史。手动重新指定日期不改动累计次数。若累计次数已为 5，上限仍为 5，则下一次自动处理直接删除日期，不再额外顺延一次。

## 8. 待办箱、批量操作和命令

日历列表底部增加“查看待办箱（N）”文本入口；N 建议显示未完成数量。点击在侧栏页签切换至简洁待办箱列表，提供返回日历，不再开一层复杂设置弹窗。待办箱也显示完成项，可完成、打开文档、右键指定日期或删除。

批量“将此前所有未完成待办移到今天”只处理日期早于今天的未完成事项，不改动累计次数；不触碰未来事项与未安排的待办箱，避免把所有暂缓事项重新推回今天。

“完成今日所有待办”处理日期等于今天且未完成的事项，包含当前扫描范围内所有项目遗留项；不受视图筛选影响。执行前展示日期和数量，执行后报告成功与失败，不能因某条失败把全批标成成功。

原有命令压缩为四条：打开侧栏日历、打开大屏日历、将此前所有未完成待办移到今天、完成今日所有待办。

用户已确认追加“查看待办箱”为第 5 条命令。番茄钟从独立图标或状态栏进入；插入代码块、迁移与索引修复不继续占用常用命令列表，迁移入口放高级设置／升级提示。

2026-10-12 对话已确认“允许 5 次，第 6 次入箱；入箱不改计数；保留 5 条命令”。本方案已据此更新，尚未执行源码修改。

## 10. 删除、迁移与数据保护

默认删除将整篇文档放入 Obsidian 配置的回收站，不永久删除。实验性保留文档模式只删除四个专属字段，笔记保留正文、文件名和其他属性，并从日历／待办箱移除。提示语区分“删除文档”与“移除重要事项”。日期和状态专属命名保证不会误删原笔记的通用 date、status 或 tags。

升级到新模型需要一次可审阅迁移，不在插件启动时自动清空旧属性：

1. 扫描已配置范围，分别报告 Daylane 0.1.0 与 Calendar Plus 旧标记文件，不混淆来源。
2. 生成文件清单、字段映射和备份，确认后逐文件执行。备份放在不被 Markdown 索引误识别的位置。
3. 旧 scheduled 或单日 date 映射为 daylane-date；旧 open／completed 映射为专属状态；旧 rollover-count 映射为专属计数。
4. 旧 cancelled 与跨日 start/end 文件列为需要人工选择的项，不猜测取消是否等于完成，也不丢弃跨日范围信息。确认日期后再降为单日；取消项可由用户选择重新安排、入箱或移除事项身份。
5. 专属旧属性可以在确认后清理；title、status、date、created、updated 等通用键必须按已知插件生成来源与预览处理，不能全库见到同名键就删除。date created、date modified、其他 tags 和正文保持原样。
6. 新默认工作日、统一自动流转和次数上限的启用在迁移确认后生效，不能让升级直接将旧事项大量移入待办箱。

未来新笔记只使用四个专属字段；旧结构只作为迁移兼容入口，不让多个格式永远同时充当可写事实模型。

## 11. 修改模块与实施顺序

| 模块 | 主要变化 |
| --- | --- |
| domain | 单日事项＋可选日期；两种完成状态；移除种类、项目、颜色、截止与历史展示字段 |
| repository | 标记＋可配置范围识别；按路径增量索引；数字重名；直接配置目录；二级标题；降级为普通笔记 |
| rollover | 严格后继日期、累计实际自动改期次数、离线补处理、上限入箱；手动安排保留计数 |
| ui | 紧凑红点日历、下方事项列表、复选框、右键菜单、待办箱入口 |
| modals | 新建只有名称，另有独立的小日期选择弹窗 |
| main | 默认侧栏、精简命令、两个设置卡片、移除遗留配置入口 |
| migration | 字段迁移、异常项预览、旧文件名可选规范化、备份与逐项结果 |
| timer | 保留独立结构，提示音默认开启，移除不再需要的命令入口 |
| holidays | 保留离线官方数据及未收录年度处理 |

推荐顺序：先完成模型与迁移预览，再完成文件识别／重名／正文；重做日历与简易输入；完成流转上限与待办箱；最后整理默认侧栏、右键菜单、配置卡片、作者信息与命令。每一步都可在测试 Vault 验收，避免旧事项在模型切换时暂时消失。

## 12. 必须验收的场景

- 相同主题与尺寸下对照参考图，侧栏和大屏具有相同的日期与事项列表样式。
- 默认侧栏出现但不抢主编辑焦点，反复启用与恢复布局不产生重复页签。
- 名称单输入框支持 Enter；文件正文为二级标题；隐藏配置不在新 YAML 中继续写入。
- 目标路径已有普通文档／事项／文件夹时生成数字后缀，不覆盖；并发占名只重试真实重名错误。
- 文件更名、正文标题修改、目录内移动不丢事项；移出范围与全库模式行为有区别。
- 只按标记识别；普通笔记不受影响；日期缺失进入待办箱、非法日期报告问题。
- 第 5 次自动顺延成功后计数为 5，第 6 次需要自动顺延时只移除日期，计数仍为 5；完成项、同日重复触发、读取失败不增加次数。
- 离线补处理只按实际执行的一次自动改期计 1；持续运行的每次成功改期分别累计，10 月 10 日调休被视为工作日。
- 未收录年度工作日顺延暂缓，不加次数、不伪报成功。
- 手动指定日期、批量移到今天、进入或离开待办箱均保持累计次数；待办箱不自动顺延；已达上限的重新安排项在下次到期时再次入箱。
- 仅移到今天的命令不处理未来项与待办箱；完成今日命令只处理今天项并报告部分失败。
- 删除模式切换后既能回收整个文档，也能只移除事项属性；正文与其他 YAML 保持不变。
- 全库模式不在每次事件或日历刷新时全量读文件，大库首扫有可见进度，冷启动缓存未就绪仍能发现事项。
- 番茄钟独立配置、默认开启和默认短音生效；声音不可用仍有文字提示。

本次修改属于模型精简和交互重构，而不是在旧页面隐藏几项设置。按上述顺序推进，能够减少长期维护复杂度，并保留已验证的索引与计时基础。
